# Native webOS service

Rust Luna supervisor with a separate capture worker, typed event pipe, hardware
lock and five-second TERM-to-KILL deadline. It owns all service operations,
configuration, persistence and permission setup. The browser UI uses native Luna
subscriptions with reconnect; there is no Node service or setup helper.

The single [package build](../../docs/developers/packaging.md#webos) produces both
binaries and the IPK under `target/webos-ipk/`. The installed TV
setup is changed only by an explicit installation, not by building.

With no arguments, the binary runs the production identity and paths as root,
without automatic expiry. `--run-for 1..300` selects a separate read-only probe.
`--sandbox /tmp/prysm-supervisor.XXXXXX --run-for 30` enables mutations and child
processes only inside an existing private (0700) temporary directory. Sandbox
workers and scanners are named `worker` and `scan-services`; its app identity is
`io.prysm.capture.probe.app`. Never launch the unbounded production mode as a probe.

## Build and FFI generation

Build using the same relocated buildroot-nc4 SDK as the existing capture worker:

```sh
WEBOS_SDK=/path/to/arm-webos-linux-gnueabi_sdk-buildroot \
  bash packaging/webos/build-ipk.sh
```

`src/generated` is generated by bindgen 0.73.2 (inherited from the workspace) from the SDK's Luna and GLib
headers, targeting ARM soft-float. Regenerate it with:

```sh
WEBOS_SDK=/path/to/arm-webos-linux-gnueabi_sdk-buildroot \
  cargo run --locked -p prysm-webos-service --features codegen \
  --bin generate-luna-bindings
```

Bindgen is optional and is absent from the deployed service dependency graph.
Only its runtime libclang feature is enabled; formatting uses rustfmt. Codegen
specifies ARMv7/Cortex-A9, soft-float with NEON, the SDK sysroot, Rust 1.85 syntax
and edition 2024. Host include-path discovery is disabled. Bindings use a narrow
allowlist and opaque native handles, and are emitted without text replacements.
Both headers must parse successfully before any output is written.

Regeneration requires libclang and rustfmt. Use the same SDK and tool versions
to reproduce output; verify checked-in files without modifying them with:

```sh
WEBOS_SDK=/path/to/arm-webos-linux-gnueabi_sdk-buildroot \
  cargo run --locked -p prysm-webos-service --features codegen \
  --bin generate-luna-bindings -- --check
```

The generated function tables retain their loaded libraries. The handwritten Luna
boundary is confined to `src/luna.rs`; all callbacks run on one private GLib
context. `src/worker/native.rs` contains the separately audited fork/exec and FD
boundary, with atomic close-on-exec pipes and parent-death SIGKILL on Linux. No SDK or target Luna libraries are required for host unit tests.

The proof loads `/usr/lib/libluna-service2.so.3` and `/usr/lib/libglib-2.0.so.0`
by absolute path from the TV. Other
library ABIs have not been validated. These are TV SDK bindings, rather than
assumed layouts copied from webOS OSE documentation.

## Process adapter

The service configuration and worker startup contract share `Source`, `Compression`, and a
validated `ReceiverAddress` from `prysm-webos-protocol`. An unconfigured receiver
is `None` internally and remains `""` in the app's saved JSON. Invalid addresses
and enum values are rejected while parsing; existing saved JSON is preserved.
The worker accepts no CLI arguments: the supervisor supplies a bounded
`PRYSM_WORKER_CONFIG` environment value and requires event/stdin control pipes.
Both binaries must be updated together when this private startup contract changes.

`config.rs` owns values and startup conversion; `files.rs` owns persistence and
Luna/boot registration; `App` receives typed operations. Luna checks authorization
before parsing a configuration into an application request.

The protocol crate's `worker` module owns the private events, readiness states,
and control-byte mapping used by both processes. Luna JSON is parsed into a video
observation before reaching application state; native Luna handles stay local to
the FFI boundary.

`std::process::Child` owns the process and `nix` supplies pipes, descriptor flags,
signals and parent-death protection. The small `pre_exec` boundary only clears
CLOEXEC on the inherited writer and installs Linux parent-death SIGKILL with a
PPID recheck. `PRYSM_EVENTS_FD` carries the actual descriptor; no fixed FD mapping
or raw descriptor ownership conversion is needed.

A general pipeline crate such as [duct](https://docs.rs/duct/latest/duct/) would
not replace Prysm's bounded event parser, GLib polling, stop deadlines or reap-before-
restart policy. [command-fds](https://docs.rs/command-fds/latest/command_fds/) is useful
for arbitrary descriptor mappings, which this adapter no longer needs. No new
process runtime/dependency is added.

`prysm-webos-service --setup` writes only recognized standalone registrations,
uses the TV's `timeout` command to bound rescan/activation, and keeps the activation
pipe open until a validated reply. The packaged shell entry point is only a fixed
`exec` wrapper retained for the app and saved boot-hook path.

## Unsafe boundary contract

Only `luna::run` is visible outside the Luna boundary; it takes Rust values and returns
a Rust result. It has **no caller-side memory-safety preconditions**: callers
cannot supply native pointers, manufacture messages, select native callbacks,
move native state between threads, or manually free native resources. Lifetimes,
ownership and cleanup are enforced inside the wrapper. Documentation below
describes its implementation obligations, rather than rules callers must follow
to avoid undefined behavior.

Application, configuration and supervisor logic deny unsafe code. The generator also
forbids unsafe code; generated raw declarations and loading tables remain private.
Both handwritten and generated code deny implicit unsafe operations inside unsafe
functions. Handwritten unsafe blocks require safety comments through Clippy.

| Concern | Invariant |
| --- | --- |
| Callback storage | One stable, shared `Rc` allocation. Initialization and cleanup never take an exclusive reference to that allocation. Neither service nor callback state can cross threads. |
| Dispatch | LS2 and the shutdown source attach to a private context driven only by the service's run thread. No default-context dispatch or nested main loop is used. |
| Messages | A callback-local `Message` wrapper has a documented unsafe constructor. Raw messages never enter safe application logic, and only owned JSON leaves payload parsing. LS2 owns subscription references; deferred mutations acquire exactly one explicit ref, released after reply/error or before unregister. |
| Native errors | Successful initialization precedes every read. An owned guard copies error text before freeing native storage, including on Rust unwind. |
| Teardown | Mark callbacks closing, destroy/unref the timer, release deferred messages, cancel the power call, unregister Luna, then release callback storage, loop/context references and library handles. Partial initialization follows the same ownership rules. |
| Failure | A callback panic aborts without running the panic payload's destructor or unwinding into C. Failed unregistration also aborts rather than freeing storage that native code may retain. |
| ABI | Function tables and struct layouts come from the target SDK. The libraries must implement that ABI, return valid NUL-terminated strings, and honor LS2/GLib ownership contracts. |

Host ABI stubs test teardown order, synchronous callback reentry during cancellation,
partial initialization failures, repeated registration, malformed/null/oversized
payloads, error cleanup and the fatal panic/unregistration paths. These tests check
the Rust boundary; they do not prove the implementation of LG's native libraries
safe.

## Miri

CI runs the service tests under pinned Miri on x86-64 Linux and ARMv7 soft-float.
Run the same interpreter locally without changing the project's default toolchain:

```sh
rustup toolchain install nightly-2026-11-01 --profile minimal --component miri,rust-src --no-self-update
cargo +nightly-2026-11-01 miri test --locked -p prysm-webos-service --target armv7-unknown-linux-gnueabi
```

Miri-only Rust stubs implement the process-library handle used by the test API
fixtures, so there is no native `dlopen` or TV library execution. They allocate
and free a real Rust-owned handle; no invalid Library value is manufactured.
The LS2/GLib function pointers still call the same Rust ABI stubs as ordinary
unit tests, exercising the production ownership and callback code. Miri checks
remain enabled, including aliasing and leak detection.

Subprocess-abort and filesystem/process integration tests run under the ordinary
host/Linux test harness rather than Miri. Miri retains isolation, aliasing and leak
checks for the in-process ownership tests. Miri cannot prove that arbitrary safe callers can never trigger UB, or
check the implementation of LG's libraries; that remains a wrapper design and
review obligation, with hardware integration tested separately.

## Isolated hardware test

```sh
python3 packaging/webos/tests/native-smoke.py --host root@192.168.18.10
```

The smoke test requires root SSH key authentication; `--supervisor` also runs the
Rust setup CLI against sandbox paths with a fake scanner, then exercises a worker.
The default read-only mode requires no worker. It creates an exclusive
temporary directory under `/tmp` and one exclusive, volatile manifest at
`/var/luna-service2/manifests.d/io.prysm.capture.probe.json`. Roles, permissions,
the dynamic service definition and executable all live in the temporary directory.
The separate service identity is `io.prysm.capture.probe.service`.

The test checks native Luna activation, read-only power observation, a public-bus
request, malformed request rejection, subscription registration/cancellation,
SIGTERM shutdown, reactivation and automatic expiry. It measures RSS and removes
its registration/files in a `finally` block. If an SSH interruption prevents
cleanup, the executable expires within 30 seconds. Remove the probe manifest and
rescan services before deleting its referenced temporary files; do not replace a
manifest whose content does not belong to this probe.

It never modifies kernel, rootfs, tvservice or other read-only system partitions,
remounts anything, writes block devices, changes immutable flags, toggles TV
power, or changes the installed Prysm app, configuration or boot hooks. Luna
permissions grant only the probe identity and outbound power-service access;
it has no capture permissions or command execution endpoint.
